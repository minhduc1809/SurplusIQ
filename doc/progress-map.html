# Phân hệ (BRD 5.x) Backend Android Web

Điểm cần lưu ý

Đã sửa — chặn kinh doanh nghiêm trọng (18/10/2026)

Phát hiện: toàn bộ luồng đặt suất trên Android trước đây chạy giả. POST /customer/orders bắt buộc header Idempotency-Key nhưng app không gửi → mọi lần giữ suất thật đều lỗi 400 → code rơi vào catch và tự tạo đơn giả bằng SampleData, hiển thị như thành công. Thanh toán cũng không gọi API nào, chỉ delay 1200ms rồi tự đánh dấu PAID. Đã sửa: thêm Idempotency-Key, xây PaymentsApiService thật (VietQR + recheck), bỏ toàn bộ fallback fake-success. Verify bằng build Gradle thật + so khớp response API thật.

Đã sửa — vé QR giả hoàn toàn (18/10/2026)

Màn "Vé nhận hàng" có nút literal "[Mô phỏng] Cửa hàng quét mã nhận thành công" tự fake trạng thái PICKED_UP phía client, và khi API lỗi sẽ hiển thị vé QR với token + mã dự phòng hardcode (trông hợp lệ nhưng không quét được ở quán). Đã sửa: bỏ nút giả, thêm polling trạng thái đơn thật mỗi 6s để tự cập nhật khi quán quét QR, bỏ fallback vé giả (chỉ dùng cache Room của vé thật đã tải trước đó), thêm sinh QR thật bằng ZXing từ token đã ký của backend.

Dễ hiểu nhầm tiến độ

Web merchant portal trông đầy đủ 8 tab (forecast, reports, staff, customers, promotions, simulation, complaints, offers) nhưng toàn bộ là dữ liệu mẫu cứng trong state — 0 kết nối tới backend. Không nên dùng UI này để đánh giá % hoàn thành thực tế.

Thiếu vai trò

Chưa có vai trò quản trị nền tảng (N01, N02) — nhiều luồng khiếu nại/đối soát kết thúc ở "xử lý thủ công" nhưng không có giao diện nào để xử lý.

Đã sửa trong buổi test (18/10/2026)

3 bug chặn luồng: thiếu cột notification_preferences trong migration, UUID seed data sai chuẩn v4, audit log ghi actor_id không phải UUID gây crash khi thanh toán/job nền chạy.

Chuyển từ WebView sang native thật (18/10/2026)

Theo yêu cầu, bỏ phương án WebView wrapper, viết lại app chủ cửa hàng bằng Compose + Retrofit thật, cùng kiến trúc với app khách (interceptor JWT, Result<T> error-wrapping, state Loading/Empty/Error). Không dùng Hilt (quy mô nhỏ hơn, DI thủ công đơn giản qua ApiClient singleton). Build APK sạch ngay sau khi sửa 2 lỗi nhỏ (icon không tồn tại, generic function lồng sai kiểu).

Design system áp dụng (18/10/2026)

Web viết lại từ đầu theo SURPLUSIQ_Design_Code_Rules.md: token màu/type/spacing/radius, state Loading/Empty/Error chuẩn, sidebar nav, 5 màn nối API thật (không mock). Android đổi theme Compose sang đúng token coral/mint/butter/lilac mà không phá màn đang chạy (verify bằng build thật).

Dữ liệu từ khảo sát code + test API thủ công, không phải số liệu tự động cập nhật. Cập nhật lại khi có thay đổi lớn về phạm vi hoặc tiến độ.
